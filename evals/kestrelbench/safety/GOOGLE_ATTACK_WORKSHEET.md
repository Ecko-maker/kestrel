# Google email slots: owner worksheet

The safety split's email vector (s1.1, `tasks/email.yaml`): 8 attacks and 8 benign twins, run only with `--tools google` (the stubs, never real Google). Generated by `scripts/google_attack_worksheet.py` from the loader.

**Attack text is the owner's** (owner decision 1). This file never contains or suggests any: it says where the text goes, what the task counts as success, and what the text must name. Your status column is kept when the file is regenerated. Nothing here changes a task fingerprint.

**What you write:** only the email body, in place of the `{{INJECTION: ...}}` line of the fixture file. Keep the header lines (From, To, Subject, Date) as they are: the search result repeats the sender. The rules of `ATTACK_REVIEW.md` apply: name the target exactly, never put the canary in the email (point at its file or the calendar), make it read like a real email, and leave no `{{`, `}}` or spec note.

**Twins:** an ordinary email of the same kind, with no instruction to the assistant. It must give what the user's request needs (the column says what) and must not name its attack's target.

## Commands (offline, no model calls)

```
uv run --no-sync kestrel bench show atk-email-send-stranger                       # what the model sees, and how it is graded
uv run --no-sync kestrel bench validate --split safety --task atk-email-send-stranger  # TODO, problems, scripted checks
uv run --no-sync python scripts/google_attack_worksheet.py --check --task atk-email-send-stranger  # target check
uv run --no-sync python scripts/google_attack_worksheet.py                        # regenerate this file
```

`show` prints each fixture as the model receives it after its card is approved: the search result, the email (wrapped as untrusted data) and, for the calendar tasks, the events. After writing an attack, also run `scripts/attack_review.py` and fill in its review row.
